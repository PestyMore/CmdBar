# 隐私审计记录（v2.1）

> 面向公有仓库的分发安全说明。本文只用泛化描述，不记录任何实际的命令名、路径或账号信息。

## 触发问题

用户下载 CI 产物、首次打开便携版时，界面里已经出现了 v1 时代的若干条命令。需要判断这些数据是随二进制分发，还是来自本机已有状态。

## 结论

**没有隐私泄露到仓库或构建产物。** 命令数据只存在于用户本机的 `%APPDATA%\com.cmdbar\commands.json`，任何版本的可执行文件都不内置命令列表。

数据来自 v1 的 WebView2 `localStorage`。v2 首次启动时执行一次性迁移：把旧键读出、转成新结构、写入 Roaming 的 JSON 文件，然后删除旧键。由于数据目录是固定的绝对路径，**任何** CmdBar 构建（本地编译的、CI 下载的、便携版、安装版）在同一台机器上都会读到同一份文件，所以看起来像"exe 里自带了命令"。

CI 在全新的 GitHub 托管 runner 上构建，只执行编译与打包，从不启动应用，runner 上也不存在该数据文件。

## 审计范围与证据

| 检查项 | 方法 | 结果 |
| --- | --- | --- |
| HEAD 全树 | `git grep -n -i -E '<命令名/脚本名/用户名/邮箱前缀>' HEAD` | 0 命中 |
| 全部提交历史 | `git log --all -S '<脚本名>'` | 0 命中 |
| 被跟踪文件 | `git ls-files` 过滤 `commands.json` / `.env` / `AppData` | 0 命中 |
| 仓库工作区 | 对全部源码/文档做 UTF-8 / UTF-16LE / GBK 字节扫描 | 仅命中文档里的通用路径字面量 `%APPDATA%\com.cmdbar` |
| 前端产物 | 扫描 `dist/` 全部文件 | 0 命中 |
| 分发产物 | 扫描下载的便携 exe 与 NSIS 安装包 | 0 命中 |
| 本机副本 | `%APPDATA%\com.cmdbar\commands.json` | 唯一副本，位于仓库之外，未被 git 跟踪 |
| 提交元数据 | `git log --format='%an <%ae>' --all` | 作者邮箱来自用户本机 git 配置，**v1 原始提交中已存在**，非本次引入 |

> 审计用的临时脚本含敏感关键字，审计完成后已删除，未提交。

## 已做的加固

1. `README.md` 增加「隐私与数据边界」章节，明确数据不随 exe 分发、如何彻底清空、以及不要在命令行里写密钥。
2. 界面底部不再显示带 Windows 用户名的绝对路径，改为 `%APPDATA%\com.cmdbar`；完整路径仅在悬停提示中可见，点「打开」直达目录。避免截图外发时泄露用户名。
3. `.gitignore` 增加 `commands.json` / `commands.json.*` / `release-artifacts/`，防止有人把数据文件误拷进仓库。
4. CI 增加「隐私检查」步骤：产物目录一旦出现 `commands.json`、`.env`、数据库或备份文件，立即失败并终止上传。
5. CI 产物目录只放两个可执行文件，并显式命名为便携版 / 安装包，便于核对内容。

## 仍需注意的设计取舍

- `com.cmdbar` 是**固定的全局目录**：任何能以该用户身份运行的程序都能读取这份 JSON。这是"数据可备份、可手改、换构建不丢"的代价，也是用户明确指定的目录名。
- 请把密码、Token、密钥放在脚本自身的安全存储里，**不要写进命令行**，因为 `commands.json` 是明文且路径可预测。
- 界面会显示命令名与路径，向外分享截图前请自行确认内容。
- 若需要隐藏 Git 提交里的真实邮箱，可在 GitHub 设置启用 `noreply` 邮箱，并自行修改本地 `git config user.email`。本项目不修改用户 git 配置；历史提交中的邮箱需要单独重写历史才能去除。
